# Kytsunia

Telegram бот з характером для приватних чатів.

## Розробка

Потрібен Node 22+ і pnpm.

```bash
pnpm install
cp .env.example .env
# заповни .env
pnpm dev
```

## Vision (фото)

Кицюня вміє бачити фото. Працює коли модель — Sonnet (або інша з vision).

Підтягуються тільки явно адресовані фото — три канали в порядку пріоритету:

1. **Тригер** — фото (або альбом) у самому повідомленні до Кицюні.
2. **Reply-chain** — якщо тегнули в reply, Кицюня йде назад по ланцюгу
   `reply_to → reply_to → ...` (включно через свої власні відповіді) і
   знаходить найближче фото в треді. Так Кицюня «памʼятає» картинку поки
   ти продовжуєш про неї питати.
3. **TTL fallback** — якщо нема ні тригера, ні reply, але хтось у чаті
   щойно (за останні ~2 хв) кинув фото — Кицюня подивиться на нього.

«Стара» історія чату фото в контекст **не несе** — інакше модель фіксується
на них при кожному текстовому реплаї.

Власні відповіді Кицюні зберігаються в `messages` (з `sender_id` = bot id) —
це потрібно для роботи reply-chain і покращує контекст у звичайних розмовах.

Налаштування (env):

- `KYTSUNIA_VISION_ENABLED` (default `true`) — фіче-флаг
- `KYTSUNIA_MAX_PHOTOS_TOTAL` (8) — cap на кількість фото в одному запиті
- `KYTSUNIA_MAX_PHOTOS_PER_ALBUM` (5) — cap на один альбом
- `KYTSUNIA_VISION_ALBUM_DEBOUNCE_MS` (1500) — затримка для збору сіблінгів альбому
- `KYTSUNIA_VISION_THREAD_DEPTH` (5) — макс. кроків у reply-chain
- `KYTSUNIA_VISION_TTL_MS` (120000) — вікно TTL fallback; `0` вимикає

Скачані фото кешуються в SQLite за `file_unique_id` — повторні відповіді в
тому ж треді не качають Telegram заново.

## Гілка відповіді

Коли користувач відповідає на повідомлення, модель бачить не лише останні 10
повідомлень чату, а й гілку `reply_to → reply_to → ...`, на яку він відповідає,
від старішого до новішого. Без цього «а чому саме так?» у reply на давню
репліку Кицюні приходило до моделі без самої репліки.

Пряма ціль відповіді береться з Telegram, тому гілка працює навіть коли
повідомлення старіше за нашу історію. Глибші кроки читаються з `messages`
за `reply_to_id`, включно через власні відповіді Кицюні. Фото в гілці лише
маркером `[фото]`, картинки з треду окремо підтягує vision (див. вище).

Глибина спільна з vision: `KYTSUNIA_VISION_THREAD_DEPTH` (5), рахує всі
повідомлення гілки разом із ціллю. Гілка йде в некешований хвіст system
prompt після контексту чату, тобто коштує кілька десятків токенів.

## Дайджест

Кицюня вміє переказати, що відбувалось у чаті:

```
Кицюня, дайджест
Кицюня, дай дайджест за 300
Кицюня, дайджест 50
```

Без числа береться `KYTSUNIA_DIGEST_DEFAULT_COUNT` (300). Явне число клампиться
до `KYTSUNIA_DIGEST_MAX_COUNT` (500) — мовчки, без скарг. Якщо в чаті менше
пʼяти повідомлень, Кицюня відмовляється, не витрачаючи виклик.

Читаються ті самі `messages`, що й для звичайного контексту, тільки не 10
останніх, а N. Фото в дайджест **не** їдуть картинками — лише маркер `[фото]`
у транскрипті: 300 повідомлень з фото коштували б абсурдних грошей.

Свою відповідь Кицюня в `messages` не пише (на відміну від звичайних реплаїв) —
інакше кілька тисяч символів дайджесту витіснили б половину recent-контексту
наступних відповідей.

Налаштування (env):

- `KYTSUNIA_DIGEST_ENABLED` (default `true`) — фіче-флаг
- `KYTSUNIA_DIGEST_DEFAULT_COUNT` (300) — скільки брати без явного числа
- `KYTSUNIA_DIGEST_MAX_COUNT` (500) — стеля на явне число; чат може замінити
  її командою «Кицюня, ліміт дайджесту», і вгору теж
- `KYTSUNIA_DIGEST_MODEL` (`claude-sonnet-5`) — окрема модель, haiku помітно
  гірше узагальнює довгий тред
- `KYTSUNIA_DIGEST_WEIGHT` (3) — скільки слотів добового ліміту зʼїдає дайджест

### Ліміти

Добові ліміти рахуються як `SUM(weight)`, а не `COUNT(*)` — інакше дайджест на
300 повідомлень важив би стільки ж, скільки «Кицюня, ти жива?». Звичайний реплай
важить 1, дайджест — `KYTSUNIA_DIGEST_WEIGHT`. Дайджест не запуститься, якщо
до ліміту (свого чи глобального) лишилось менше, ніж його вага.

Порядок цифр: 300 повідомлень ≈ 10-15k вхідних токенів, тобто ~$0.03-0.05 за
дайджест на Sonnet 5.

## Пошук

Кицюня шукає в інтернеті тільки на явну команду:

```
Кицюня, пошукай курс долара
Кицюня, пошукай          ← у відповідь на повідомлення чи фото
```

Сама модель пошук не ініціює: інструмент web search підключається до запиту
лише на цю команду. Причина — ціна. Опис інструмента додає кілька тисяч токенів
до кожного запиту, навіть коли пошук не знадобився.

Використовується базова версія (`web_search_20250305`), а не новіша з динамічною
фільтрацією: на коротких запитах новіша відповідала ~30 с проти ~5 с і коштувала
дорожче. Країну в `user_location` не передаємо — `UA` API не підтримує, тільки
часовий пояс `Europe/Kyiv`.

Джерела (до двох URL) бот дописує сам із citations відповіді, превʼю посилань
вимкнене. Кожен пошук — $0.01 поверх токенів, це враховано в `cost_usd`.

Поки модель думає (звичайна відповідь, пошук, дайджест), у чаті висить
«друкує…» — бот поновлює статус кожні 4 с.

Налаштування (env):

- `KYTSUNIA_SEARCH_ENABLED` (default `true`) — фіче-флаг
- `KYTSUNIA_SEARCH_MAX_USES` (3) — скільки пошуків за одну відповідь
- `KYTSUNIA_SEARCH_WEIGHT` (3) — скільки слотів добового ліміту зʼїдає відповідь з пошуком

## Адмінські команди

Працюють лише від `ADMIN_USER_ID`; для решти мовчки ігноруються, щоб не
розкривати існування команди.

```
Кицюня, скажи в -1001234567 текст     ← надіслати повідомлення в інший чат
Кицюня, звіт                          ← витрати на модель за 7 днів
Кицюня, звіт 30                       ← за 30 днів (стеля 90)
Кицюня, спеціальна інструкція текст   ← дописати текст у промпт моделі
Кицюня, спеціальні інструкції         ← список з id і датами
Кицюня, забудь інструкцію 3           ← видалити за id
Кицюня, модель                        ← яка модель відповідає в цьому чаті
Кицюня, модель opus                   ← перемкнути чат (sonnet / opus / haiku або повний id)
Кицюня, модель скинь                  ← повернути LLM_MODEL
Кицюня, персона                       ← показати персону цього чату
Кицюня, персона текст                 ← замінити характер (або у відповідь на повідомлення з текстом)
Кицюня, персона скинь                 ← повернути персону з коду
Кицюня, ліміт дайджесту               ← до скількох повідомлень бере дайджест у цьому чаті
Кицюня, ліміт дайджесту 2000          ← задати стелю замість KYTSUNIA_DIGEST_MAX_COUNT
Кицюня, ліміт дайджесту скинь         ← повернути глобальну стелю
```

Звіт береться з `llm_calls`: кількість викликів, вартість, частка вхідних
токенів з кешу, помилки й відмови по ліміту, розбивка по моделях (якщо їх
кілька), по чатах і по пʼяти найактивніших людях, окремо сьогодні. Чати
показуються за id, крім поточного. Звіт містить id інших чатів і імена
людей, тож питати його краще в особистих.

Спеціальна інструкція — довільний текст після команди, з переносами рядків
як є; без тексту береться повідомлення, на яке відповіли. Інструкції живуть
у скоупі чату, в якому їх дали: список і видалення теж по цьому чату.
Зберігаються в `special_instructions` і дописуються в кінець system prompt
і для звичайних відповідей (у кешований persona-блок, тож зміна списку
перебудовує кеш один раз), і для дайджесту, з приміткою, що вони мають
пріоритет над базовими правилами. Id у списку не перевикористовуються після
видалення, щоб старий список не вказав на нову інструкцію.

Модель на чат зберігається в `chat_settings` і стосується звичайних
відповідей і пошуку; дайджест лишається на `KYTSUNIA_DIGEST_MODEL`. Приймаються
лише моделі з таблиці цін у `pricing.ts`, інакше звіт про витрати рахував би їх
у нуль. Персона будується під модель чату, тож на «яка ти модель» Кицюня
відповідає правильно; кеш промпту в кожного чату свій і так.

Персона на чат замінює лише характер (`PERSONA_PROMPT` у `persona.ts`):
технічна частина про модель і вміння дописується до будь-якої персони
однаково, бо описує те, що бот справді вміє. Без перевизначення береться
текст із коду. Спеціальні інструкції дописуються після персони, якою б вона
не була. Дайджест має власний промпт і на персону чату не зважає.

Стеля дайджесту на чат зберігається в `chat_settings.digest_max_count` і ріже
і явне число («дайджест 400» у чаті зі стелею 200 дасть 200), і дефолтну
кількість, якщо вона вища. Глобальний `KYTSUNIA_DIGEST_MAX_COUNT` для такого
чату не діє взагалі, тож стелю можна й підняти. Порядок цін: 2000 повідомлень
≈ 80k вхідних токенів, ≈ $0.16 за дайджест на Sonnet 5, а вага дайджесту в
добових лімітах від розміру не залежить.

## Privacy

`/забудь мене` (opt-out) стосується **тільки персональних профілів** —
Кицюня перестає вивчати твій стиль. Повідомлення в контексті чату
(включно з фото) залишаються видимими для бота, бо без них він не зможе
підтримати розмову.

Пошук («Кицюня, пошукай») відправляє запит пошуковому провайдеру через
Anthropic. Запит модель складає з твого повідомлення і контексту чату, тож
туди можуть потрапити імена й деталі з розмови.
